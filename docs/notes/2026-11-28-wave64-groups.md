# Wave64 replay on 32-lane NVIDIA

## Result

`LEONIDA_WAVE64_GROUPS=1` is an exact, opt-in replay path for eligible console Wave64 compute programs on a host whose maximum wave is 32. On the tested code at base `4a661ea`, it changed four of the seven named Wave64 programs from valid DXIL with a refused host pipeline to valid DXIL with a created host pipeline. The A/B sample was captured before main merged PR #115 (`40aaa84`): replay on measured slower (109.5 versus 94.2 ms/frame), but two samples per setting are not enough for a general claim, and the pictures show no clear visual change. Attempts to refresh the pair on `40aaa84` encountered device removals before valid samples. These results do not support enabling the switch in an NVIDIA profile.

The builder remains safely disabled. On the branch rebased onto `40aaa84`, with `LEONIDA_BVH_BUILDER=1`, `LEONIDA_BVH_QUARANTINE=1`, and `LEONIDA_WAVE64_GROUPS=1`, its all-or-none gate reports 3 missing of 53. Turning on `LEONIDA_WAVE_WIDE=1` under quarantine leaves the same three missing.

## Builder programs that remain refused

The three builder shaders fail during emission, before host pipeline creation. Their runtime program hashes and exact translated-code offsets are:

| Hash | Group size | Offset | Refusal |
| --- | ---: | ---: | --- |
| `39321a95223001ed` | 256 threads | `0x23c` | first-lane read where not every lane runs |
| `77360df21e12ea43` | 512 threads | `0x23c` | first-lane read where not every lane runs |
| `9fc111d3be79364f` | 512 threads | `0x258` | first-lane read where not every lane runs |

The group-wide retry reports that it is not tried for the `[256, 1, 1]` and `[512, 1, 1]` thread groups. The existing retry supports a single console Wave64 group (64 threads); these groups span four or eight console waves. The exact cross-half exchange writes and reads LDS around barriers. In a divergent region, one or more waves can skip that barrier while another reaches it, which can hang the D3D12 thread group. The opt-in retry therefore leaves these shaders refused. No approximation or real builder writes were used.

## Paired measurement

Five launch attempts on base `4a661ea` used the same `nvidia-8gb` profile, `-SkipScenes -Seconds 330 -From 170`, and the same switches other than `LEONIDA_WAVE64_GROUPS`. `LEONIDA_BVH_HOLD=1` and builder quarantine were enabled for both settings so no rays walked structures that the incomplete builder had not built. DRED and the driver watch were enabled. The run data and captures stayed under the local `%LOCALAPPDATA%\leonida\runs` directory and are not included here. Main later merged PR #115 (`40aaa84`), which changes shadow code. The new-base attempts described in Checks lost the device before producing valid paired samples, so the figures below are historical and not a measurement of the updated base.

| Setting | Run | FPS | ms/frame | Lines | Validity |
| --- | --- | ---: | ---: | ---: | --- |
| Off | 1 | 10.8 | 92.7 | 17 | invalid: device removed (`-2005270523`); excluded |
| Off | 2 | 10.7 | 93.6 | 30 | valid |
| Off | 3 | 10.6 | 94.8 | 30 | valid |
| On | 1 | 9.1 | 109.5 | 30 | valid |
| On | 2 | 9.1 | 109.5 | 29 | valid |

For the two valid samples per setting, the median was 94.2 ms/frame with replay off and 109.5 ms/frame with replay on (about 10.6 versus 9.1 FPS). In this pair the on setting was 15.3 ms/frame, or about 16%, slower. The two valid samples within each setting were close, but two samples per setting are too few for a broad hardware claim; the result argues against adding an NVIDIA profile or recommending this switch for performance on this machine. The control device-loss attempt is excluded and disclosed above.

The world-600 captures show the same character close-up: both have a warm highlight across the face and deep shadow on the right, with a small change in expression and eye position. World-1000 is a black loading screen with a spinner in both. No clear lighting or particle effect change is visible. The builder was quarantined and held off, so these runs do not show ray-traced shadows.
