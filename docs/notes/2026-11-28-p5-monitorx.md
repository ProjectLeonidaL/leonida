# P-5: wait hint sites patched in place, so the title's fence wait takes no exceptions

The title waits for its fences in a loop of `monitorx`, a look at the fence's value in memory and `mwaitx`.
Only AMD processors have the two instructions: on an Intel processor each is an illegal-instruction
exception, which the vectored handler (`crates/leonida-loader/src/crash.rs`, `handler`) passes to
`console_insn::emulate` (`crates/leonida-loader/src/console_insn.rs`). There `monitorx` only records the
address for the wait statistics and `mwaitx` spins once (`std::hint::spin_loop`, a `pause`); both are then
stepped over. The decoded bytes of a site are already cached per thread, so what is left is Windows'
exception dispatch itself: about a microsecond a pass, and two passes for each turn of the loop.

New behind `LEONIDA_MWAITX_PATCH=1`, off by default, in `crates/leonida-loader/src/console_insn_patch.rs`.

## What the title waits on

From the existing wait lines of five diagnostics runs on this machine (i7-13620H, RTX 5060 Laptop, before
this change): one thread waits, always on the same fence value. While the graphics side keeps up its waits
are short (0.8 to 13 ms, 3 to 100 turns of the loop). While it is behind they last about 150 ms, with about
70,000 `mwaitx` each: 110,000 to 200,000 exceptions a second on average over a run, and up to 418,000 a
second at peaks. That is a whole core in Windows' exception dispatch.

## What changed

With the switch, the first exception at a wait hint site rewrites its three bytes to what the emulation
does: `monitorx` (`0f 01 fa`) becomes a three-byte `nop` (`0f 1f 00`), `mwaitx` (`0f 01 fb`) becomes `pause`
and `nop` (`f3 90 90`). From then on the loop spins with `pause` inside the title's code, with no exception.
The exception that patched the site is emulated as before.

- Only a site that faulted is patched: no scan of the image, so no data and no bytes in the middle of an
  instruction are taken for code. Other prefixed or longer forms are left to the emulation.
- The bytes change in one locked write of the aligned 8 bytes around them, or 16 (`cmpxchg16b`) when they
  cross an 8-byte boundary. Another thread sees the old instruction or the new one, never a mix. A thread
  that fetched the old one before the write still faults; the handler finds the new bytes and runs them
  again. A site in the last two bytes of 16 is left to the emulation.
- The page is made writable for the write and given its protection back, as the thread-local storage
  patch (`tls.rs`) and the `clwb` patch already do. One site is patched at a time; a thread that finds
  another patching leaves its site to the emulation for that turn.
- Behaviour does not change: the emulation already skipped `monitorx` and spun on `mwaitx`. Each turn of
  the loop is now tens of nanoseconds instead of about two microseconds, so the fence is looked at more
  often.

shortcut: on the console `mwaitx` lets the core rest until the value is written or its timer runs out;
here it spins with `pause`, as the emulation did.

Off by default because it writes into the title's code: a title that checks its own code would see the
change.

## Measuring it

Once a second (from the handler, so only while some exception still comes; the `clzero` loops give about
600 a second) the log says `console wait hints (LEONIDA_MWAITX_PATCH=1): monitorx and mwaitx exceptions N
a second; sites patched P ..., left to the emulation L, exceptions on patched sites S`. The existing line
every five seconds (`console CPU instructions, exceptions a second: ... monitorx ..., mwaitx ...`) gives
the before figure. With the switch the `mwait: thread ... waited` lines stop for patched sites: their waits
no longer pass through the handler.

## Other ways looked at

- Intel's `umonitor` / `umwait` (WAITPKG): four bytes each, so they do not fit in the three of a site, and
  `umwait` takes a deadline in edx:eax and its own control in a register, which the title's loop sets for
  `mwaitx`. Would need a jump to a stub and saved registers. Not done.
- `WaitOnAddress`: needs a call out of the title's loop and knowing its shape. Not done.
- A cheaper handler: the decoded bytes are already cached, and the cost is the dispatch, which no handler
  change removes.

## Measured

Not measured in the game yet. Unit tests cover the replacement bytes, the aligned word chosen, the locked
8- and 16-byte writes on authored bytes, and a wait loop of our own in a read-only executable page: it is
patched, its protection is given back, and it runs.
